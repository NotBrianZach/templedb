#+TITLE: Org-in-DB: TempleDB-Native Task & Notes System
#+AUTHOR: TempleDB
#+DATE: 2026-07-28

* Motivation

Org files on disk are:
- Not versioned by TempleDB (separate from project VCS)
- Not queryable via SQL
- Not syncable across machines (without git or syncthing)
- Not accessible to Temple Agent (can't search/filter tasks programmatically)
- Duplicating state that TempleDB already manages (projects, deploys, incidents)

TempleDB already stores everything else in SQLite. Tasks and notes should be there too.

* What We Keep From Org

Org is great at:
- Hierarchical outline editing (folding, promotion, TAB cycling)
- TODO state cycling (C-c C-t)
- Scheduling and deadlines (C-c C-s, C-c C-d)
- Tags
- Properties
- Agenda views (filtering, grouping, sorting)
- Capture (quick entry)

We keep ALL of these as the UI layer. Org-mode is the renderer.
The database is the storage.

* Schema

** Core Table: =org_items=

#+begin_src sql
CREATE TABLE org_items (
    id INTEGER PRIMARY KEY,
    -- Hierarchy
    parent_id INTEGER REFERENCES org_items(id),
    position INTEGER NOT NULL DEFAULT 0,    -- ordering within parent
    depth INTEGER NOT NULL DEFAULT 1,       -- org heading level

    -- Content
    headline TEXT NOT NULL,
    body TEXT,                               -- text below heading
    todo_state TEXT,                         -- TODO, NEXT, WAITING, DONE, etc.

    -- Organization
    category TEXT NOT NULL DEFAULT 'inbox',  -- inbox, task, project, someday, etc.
    tags TEXT,                               -- comma-separated: @home,PROJECT
    priority TEXT,                           -- A, B, C

    -- Scheduling
    scheduled_at TEXT,                       -- SCHEDULED timestamp
    deadline_at TEXT,                        -- DEADLINE timestamp
    closed_at TEXT,                          -- CLOSED timestamp

    -- TempleDB integration
    project_id INTEGER REFERENCES projects(id),
    session_id INTEGER REFERENCES agent_sessions(id),

    -- Properties (flexible key-value via JSON)
    properties_json TEXT,                    -- {"TEMPLEDB_PROJECT": "bza", ...}

    -- Metadata
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now')),
    archived INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX idx_org_items_parent ON org_items(parent_id);
CREATE INDEX idx_org_items_category ON org_items(category);
CREATE INDEX idx_org_items_todo ON org_items(todo_state);
CREATE INDEX idx_org_items_project ON org_items(project_id);
CREATE INDEX idx_org_items_scheduled ON org_items(scheduled_at);
CREATE INDEX idx_org_items_deadline ON org_items(deadline_at);
#+end_src

** Why One Table, Not Many

One table with a =category= column instead of separate tables because:
- Refiling is just =UPDATE category=, not cross-table moves
- Agenda queries span all categories naturally
- Hierarchy (parent_id) works across categories
- Simpler schema, fewer joins

** Properties

Org properties map to JSON:
#+begin_src json
{
  "TEMPLEDB_PROJECT": "bza",
  "STYLE": "habit",
  "EFFORT": "1h",
  "CUSTOM_KEY": "value"
}
#+end_src

Known properties get dedicated columns (project_id, scheduled_at).
Everything else lives in properties_json.

* Emacs Interface

** Buffer: =*TempleDB Org*=

Not a file-visiting buffer. Renders from DB, writes back to DB.
Uses real org-mode so all keybindings work.

#+begin_example
#+TITLE: Inbox
#+TDB_CATEGORY: inbox

* TODO Buy groceries                                          :@errands:
  SCHEDULED: <2026-07-29 Tue>
* TODO [bza] Fix login redirect
  :PROPERTIES:
  :TEMPLEDB_PROJECT: bza
  :END:
* TODO Read that paper on embeddings                          :@computer:
* NOTE Check out new Nix release                              :NOTE:
#+end_example

** How Editing Works

1. User opens a category (e.g. =SPC o I= for inbox)
2. Buffer rendered from =SELECT * FROM org_items WHERE category='inbox'=
3. User edits normally (add headings, change TODO states, type text)
4. On save (=C-x C-s= or auto-save timer):
   - Parse the org buffer back into structured items
   - Diff against DB state
   - Write changes (INSERT/UPDATE/DELETE)
5. No file touches disk

** Alternatively: Incremental Sync

Instead of re-parsing the whole buffer on save:
- Hook into =org-after-todo-state-change-hook= → UPDATE todo_state
- Hook into =org-after-refile-hook= → UPDATE category, parent_id
- Hook into =org-capture-after-finalize-hook= → INSERT
- Hook into buffer modification → debounced UPDATE body/headline
- =org-archive-subtree= → UPDATE archived=1

This is more complex but avoids the parse-everything-on-save problem.

** Recommended: Hybrid Approach

Start with full re-parse on save. It's simpler and org buffers are
small (hundreds of items, not thousands). Optimize to incremental
sync later if performance is an issue.

Templates become DB rows too (or just hardcoded in elisp).

* Agenda

Agenda queries the DB instead of scanning files:

#+begin_src elisp
(defun templedb-org-agenda ()
  "Show agenda from TempleDB org_items table."
  ;; SELECT * FROM org_items
  ;; WHERE (scheduled_at <= date('now','+7 days')
  ;;        OR deadline_at <= date('now','+7 days')
  ;;        OR todo_state = 'NEXT')
  ;;   AND archived = 0
  ;; ORDER BY scheduled_at, deadline_at, category, position
  ;;
  ;; Render as org-agenda buffer
  )
#+end_src

Custom agenda views become SQL queries:
- Daily: =WHERE scheduled_at = date('now')=
- Next actions: =WHERE todo_state = 'NEXT'=
- Waiting: =WHERE todo_state = 'WAITING'=
- Project overview: =WHERE category = 'project' AND archived = 0=
- By TempleDB project: =WHERE project_id = ?=
- Overdue: =WHERE deadline_at < date('now') AND todo_state NOT IN ('DONE','CANCELLED')=

* Refile

Refile = UPDATE category:

#+begin_src sql
UPDATE org_items SET category = 'project', updated_at = datetime('now')
WHERE id = ?
#+end_src

Cross-category refile with parent:
#+begin_src sql
UPDATE org_items
SET category = 'project', parent_id = ?, position = ?, updated_at = datetime('now')
WHERE id = ?
#+end_src

* Archive

Archive = soft delete:

#+begin_src sql
UPDATE org_items SET archived = 1, closed_at = datetime('now'), updated_at = datetime('now')
WHERE id = ?
#+end_src

View archive: =SELECT * FROM org_items WHERE archived = 1 ORDER BY closed_at DESC=

* TempleDB Integration

** Agent → Tasks

When Temple Agent completes a run, it can auto-create items:

#+begin_src sql
INSERT INTO org_items (headline, body, category, project_id, session_id, todo_state)
VALUES ('Fix login redirect', 'Identified in agent session #17', 'task',
        (SELECT id FROM projects WHERE slug='bza'), 17, 'TODO')
#+end_src

** Tasks → Agent Context

When starting an agent session, include relevant tasks:

#+begin_src sql
SELECT headline, todo_state, scheduled_at, deadline_at
FROM org_items
WHERE project_id = ? AND archived = 0 AND todo_state NOT IN ('DONE','CANCELLED')
ORDER BY CASE todo_state WHEN 'NEXT' THEN 0 WHEN 'TODO' THEN 1 ELSE 2 END
#+end_src

This goes into the context basket as "Project tasks" alongside
file tree, commits, etc.

** Deploy → Log Entry

After a deploy, auto-create:
#+begin_src sql
INSERT INTO org_items (headline, body, category, project_id, todo_state)
VALUES ('Deployed bza 2026-07-28', 'commit abc123...', 'journal', ?, 'DONE')
#+end_src

** Work Log → Tasks

If the work log detects files were modified but not committed:
#+begin_src sql
INSERT INTO org_items (headline, category, project_id, todo_state)
VALUES ('[bza] Review and commit agent changes', 'inbox', ?, 'TODO')
#+end_src

* CLI

#+begin_src shell
templedb org list                         # all non-archived items
templedb org list --category inbox        # just inbox
templedb org list --project bza           # items for a project
templedb org list --todo NEXT             # next actions
templedb org add "Buy groceries" --category inbox --tags @errands
templedb org add "[bza] Fix bug" --project bza --todo TODO
templedb org done 42                      # mark item done
templedb org refile 42 --category project # move to projects
templedb org archive 42                   # soft-delete
templedb org agenda                       # today's agenda
templedb org agenda --week                # weekly view
#+end_src

* Implementation Order

1. Create =org_items= table (migration)
2. Write =templedb-org.el= with buffer rendering from DB
3. Implement save-to-DB (parse org buffer back to rows)
4. Implement capture (direct to DB)
5. Implement agenda (SQL queries rendered as org-agenda)
6. Implement refile (UPDATE category)
7. Wire TODO state change hook
8. Wire scheduling hooks
9. Add to context basket (project tasks item)
10. Add CLI commands
11. Add MCP tools
12. Add auto-creation from agent/deploy events

* What We Do NOT Build

- org-roam (networked notes) — different problem, keep file-based
- org-journal — keep as file (daily entries are fine as datetree files)
- org-drill — keep as file (flashcards are their own thing)
- org-gcal — keep as file (calendar sync is external)

The system handles structured GTD items. Free-form long documents
stay as files. The boundary: if it has a TODO state or goes in
the agenda, it lives in the DB.
