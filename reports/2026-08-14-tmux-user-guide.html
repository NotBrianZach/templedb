tmux, the TempleDB way — a user guide

How tmux is wired into TempleDB and what to do with it. Covers the shared config that lives in the DB and deploys to every personal machine, the vibe start --tmux on-demand wrap, and a handful of workflow patterns that pay off once you're inside tmux. Written for someone who installs the config once and wants to know what they can now do.

The setup, in one paragraph

Canonical config lives in the templedb DB at config/tmux.conf. On every nixos-rebuild switch, home-manager materializes it to ~/.config/tmux/tmux.conf on all personal machines (zMothership2, zMothership3, zStation, zachMothership, WilliamZacharyAbelTheZeroth). The same file backs templedb ai vibe start --tmux, which wraps a Claude Code launch in a fresh tmux session for users who want scrollback without keeping tmux running around their normal shell. One source of truth, three places it gets used.

The prefix and the two keys you actually need

Prefix is Ctrl+Space. If you learn nothing else, learn these two combinations:

ChordDoes
Ctrl+Space Esc Enter copy mode — scroll through pane history with vi keys (k/j, Ctrl+u/d, gg/G, / to search). This is the whole reason tmux is here for TUIs like Claude Code.
Wheel scroll up Auto-enters copy mode, scrolls, exits when you type again. Same result as above, no keyboard.

Everything else (windows, panes, sessions) is icing. You can get real value from tmux just using these two.

Using it with Claude Code

The intended path

# Explicit wrap — one command, ephemeral session, exits with claude
templedb ai vibe start --tmux templedb

# Then to look back through what Claude has printed:
#   • wheel-scroll up (mouse), OR
#   • Ctrl-Space Esc, then vi navigation

The you keep tmux running anyway path

# Start tmux once for the day, then use it as your shell environment:
tmux                                     # or tmux new -s work

# Inside, launch Claude Code normally:
templedb ai vibe start templedb          # no --tmux; we're already in one

# The --tmux flag detects $TMUX and skips wrapping, so it's safe either way.

Attached vs detached

Ctrl-Space d              # detach (session keeps running in background)
tmux attach               # reattach to the last session
tmux ls                   # list sessions
tmux attach -t work       # attach to a named session
tmux kill-session -t work # nuke a specific session
Why this matters over SSH Detach + reattach means your Claude Code session survives an SSH drop, laptop lid close, Wi-Fi hiccup, or terminal-emulator crash. Start Claude Code in tmux on zMothership2 once, and you can reach the same running session from any subsequent SSH login. This is the workflow advantage that alt-screen scrollback in a different terminal doesn't give you.

Panes and windows — for when one shell isn't enough

Split panes

Ctrl-Space "        # split horizontally (stacked)
Ctrl-Space %        # split vertically (side by side)
Ctrl-Space o        # cycle to next pane
Ctrl-Space arrow    # focus pane in a direction
Ctrl-Space z        # zoom current pane to full-window (toggle)
Ctrl-Space x        # kill current pane

Windows (tabs)

Ctrl-Space c        # create new window
Ctrl-Space n / p    # next / previous window
Ctrl-Space 1..9     # jump to window by index (base-index=1)
Ctrl-Space ,        # rename current window
Ctrl-Space &        # kill current window (confirms)

Copy mode — the scrollback layer

Once inside copy mode (Ctrl+Space Esc or wheel-up), you have the pane's own history, independent of whatever alt-screen TUI is running. Bindings are vi-flavored per the config's mode-keys vi:

KeyDoes
k/jup/down one line
Ctrl+u/dhalf-page up/down
gg/Gtop/bottom
/pattern Entersearch backward for pattern
n/Nnext / previous match
vbegin visual (character) selection
Vbegin line selection
yyank selection into the tmux paste buffer
Esc or qexit copy mode
 
Ctrl-Space ]        # paste the last yanked text at the cursor
Ctrl-Space =        # interactive paste-buffer chooser

Workflow patterns worth learning

Pattern 1: Long-running task + watch it

You start a long build and want to keep working. Split a pane, run the build in one, work in the other. 

# In your current window:
Ctrl-Space "                              # split stacked
templedb ast build --host zMothership2 --nix-build

# Ctrl-Space o back to the top pane, do other stuff.
# When the build finishes, glance at the bottom pane.

Pattern 2: Claude Code on the left, live logs on the right

# Start tmux, launch Claude Code, split, tail logs on the right:
tmux
templedb ai vibe start templedb          # left pane, Claude Code
Ctrl-Space %                             # split right
journalctl -fu templedb-gui              # right pane, live GUI logs

# Now you can ask Claude Code to change GUI code and watch the reload
# in the same visual field.

Pattern 3: Named sessions per context

tmux new -s ai       # session named "ai" — Claude Code lives here
tmux new -s ops      # separate session for deploys / systemd inspection
tmux new -s notes    # yet another for browsing docs / reports

# Switch between them without exiting:
Ctrl-Space s         # session picker
Ctrl-Space (         # previous session
Ctrl-Space )         # next session

Sessions survive tmux server restart via the tmux-resurrect plugin (not shipped by default; opt-in per user).

Pattern 4: SSH into a machine, resume its shared tmux session

# On zMothership2, once, start a named session:
tmux new -s home

# From your laptop, over SSH:
ssh zMothership2
tmux attach -t home

# Both keyboards feed the same session. Useful for pair-debug over SSH,
# or just for "start a task at my desk, resume from the couch."

Pattern 5: Pane synchronization for fleet operations

# Open one pane per host:
Ctrl-Space c
Ctrl-Space %      # a few times, one pane per zMothership etc.

# In each pane: ssh <hostname>
# Then turn on synchronize-panes:
Ctrl-Space :setw synchronize-panes on

# Type once, it runs on all hosts. Toggle off with the same command "off".
# (Great for a quick `nixos-rebuild switch` sanity check across the fleet.)

Pattern 6: Copy something out of Claude Code to your system clipboard

Ctrl-Space Esc                           # copy mode
/pattern Enter                           # find the thing
v                                        # begin selection
(vi movements to extend)
y                                        # yank into tmux buffer

# Now paste it out to X:
Ctrl-Space :save-buffer /tmp/copied.txt
xclip -selection clipboard < /tmp/copied.txt

# Or, better, add OSC 52 clipboard passthrough to your tmux config
# (out of scope for the default bundle — add if you want it).

Ideas that fit our particular setup

tmux + Emacs — pick one, not both

If you're inside Emacs vterm, tmux adds nothing — Emacs already gives you scrollback, splits, and buffers. The vibe start --tmux flag detects Emacs vterm (via INSIDE_EMACS) and skips wrapping in that case, so it's safe to have both muscle memories.

Dashboard pane for the GUI

Have a pane that runs templedb gui and another that xdotool or xdg-opens http://127.0.0.1:8420/reports. Every new report you write shows up on refresh. Detach the session and it's still running next time you attach.

Long agent runs

Kick off a long agent session (say, a subagent doing a big reorg) in a named tmux session, detach, and let it run. Come back and inspect the copy-mode history to see what happened without staring at the terminal for 40 minutes.

Session-per-project convention

Match tmux session names to templedb project slugs: 

# Auto-create-or-attach a session named after the project:
tmux new -A -s <project> -- templedb ai vibe start <project>

# Or wrap it in a shell function:
vibe() { tmux new -A -s "$1" -- templedb ai vibe start "$1"; }
vibe bza

Then tmux ls reads like a list of your active work threads, one line per project.

Snapshot a Claude Code turn

# In copy mode, mark the start of the interesting turn:
gg                       # or navigate to a searchable line
:save-buffer /tmp/claude-turn-$(date +%s).log

# Or capture the entire pane on demand:
Ctrl-Space :capture-pane -pS - > /tmp/pane-dump.txt

The -S - means "from the start of the pane's history to the current view." Useful if you want to include a Claude Code conversation verbatim in a report or bug write-up.

Trouble

Panes exit immediately with "sh: command not found" You have an older tmux.conf that doesn't set default-command "$SHELL". NixOS has no /bin/sh and tmux's default fallback fails. The templedb-bundled config sets this explicitly. If you're on a machine that hasn't rebuilt yet, edit ~/.config/tmux/tmux.conf to include set -g default-command "$SHELL" and reload with Ctrl-Space r.
Colors look wrong / Claude Code output looks dim Terminal probably isn't advertising true-color support. The bundled config includes set -ga terminal-overrides ",alacritty:Tc" which fixes Alacritty specifically. If you're on a different terminal, add its TERM string to the overrides.
Mouse selection copies to tmux buffer but not X clipboard Expected — y in copy mode goes to tmux's internal buffer, not the X selection. Add set -g set-clipboard on plus a terminal that supports OSC 52 (Alacritty does). Or use tmux-yank plugin. Left as an opt-in since not everyone wants cross-app clipboard sharing.
Nested tmux warning "sessions should be nested with care" You launched tmux inside tmux. The vibe start --tmux flag detects $TMUX and refuses to nest automatically, so this only comes up if you run tmux by hand inside a session. Usually harmless; if it bothers you, use tmux's :kill-server in one shell to clear things up.

Where to change things

Source of truth is config/tmux.conf in the templedb project. To edit it (safely): 

# Read what's there:
templedb file cat templedb config/tmux.conf

# Edit interactively (uses $EDITOR, round-trips through DB):
templedb file edit templedb config/tmux.conf

# Or overwrite with a piped payload + hash-verify:
cat < new_tmux.conf | templedb file set templedb config/tmux.conf --verify

# After editing, refresh the checkout so nix-build sees it and every
# machine picks it up on the next rebuild:
templedb file checkout templedb config/tmux.conf \
  -o ~/.config/templedb/checkouts/templedb/config/tmux.conf

# Reload the running tmux immediately:
tmux source-file ~/.config/tmux/tmux.conf
# ... or, inside tmux: Ctrl-Space r

Do not hand-edit ~/.config/tmux/tmux.conf directly — home-manager owns that path and will overwrite it on rebuild. If you're experimenting, iterate on a copy and paste into the DB when it's right.

Learn the prefix and the scroll-back binding, get the mouse turned on, and everything else is discoverable at your own pace. The --tmux flag exists for people who don't want to think about tmux until scrollback breaks; the standalone tmux workflow is there for people who eventually will.
