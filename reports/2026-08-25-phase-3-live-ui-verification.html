Isolation drill

With three files staged under three distinct sessions, TEMPLEDB_SESSION_ID=43 templedb vcs commit committed exactly one file (the CLI one) and printed “(2 file(s) staged in other sessions were not included).” FUSE and GUI rows survived the commit with their staged_by_session_id intact.

vcs status --all displayed the FUSE and GUI sessions as separate grouped sections with their author badges: 

Session #41 (fuse-auto-zMothership2) [active] — fuse:
  staged    fuse2-1643862-5639.txt

Session #42 (gui-zMothership2) [active] — gui:
  staged    test.txt

GUI unstage (POST /vcs/regr-test/staging/unstage/<file_id>) cleared its own session’s attribution on test.txt without touching the FUSE row. That’s the isolation guarantee I most cared about since the previous recap noted this path had never been eyeballed under load.

Rule confirmed Followup #3’s hypothesis (Phase 1 had a latent hole because FUSE / GUI writers set the boolean without staged_by_session_id) is now empirically closed: those writers correctly attribute to their per-host named sessions, and CLI-side commits under a different session don’t sweep them.
