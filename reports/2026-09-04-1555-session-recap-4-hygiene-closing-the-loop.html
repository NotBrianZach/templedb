Session recap 4: closing the hygiene loop

Continuation of 2026-09-04. Started with red noise in templedb summary, ended with a persistent snapshot table + a doctor invariant that watches for real drift while ignoring resolver-driven flicker. Also chipped python ingest to 1.11.

What was open at the start of this stretch

Recap 3 left the tool in a good place: dead-imports false-positive rate at 21%, GUI browsable, ambient hygiene block in templedb summary. Four items were flagged as actionable follow-ups; this stretch cleared three of them (fleet noise, GUI page, historical tracking) and picked away at the fourth (attribute-chain calls).

What shipped

1. Fleet noise cleanup

Four fleet_machines rows had deployment_status='new' and no last_deployed_at — legacy setup entries that were never deployed via templedb. Their reconcile probes failed with SSH auth errors or missing target_host, painting the summary red for state that isn't really broken.

  • reconcile machine all now skips machines without a last_deployed_at. One-line notice, opt in with --include-undeployed.
  • summary shows them as a muted single line instead of four red rows.

2. GUI /hygiene page

Mirrors templedb entity dead-imports and the summary block. Two routes: 

/hygiene              rollup by slug
/hygiene?slug=<slug>  every File→imports pair without a bridge

Same CTE that the CLI and summary use — updating the bridge kinds in one place changes all three surfaces. Sidebar entry added (, H).

3. Historical hygiene tracking (mig 100)

hygiene_snapshots table + a CLI: 

templedb hygiene snapshot   [--slug S]
templedb hygiene history    [--slug S]
templedb hygiene diff SLUG  [--days D]

Each row stamps the adapter_version so hygiene diff can distinguish real code drift from resolver-driven flicker. The daily reconcile.timer now records a snapshot too — same cadence, one ExecStart.

4. Python ingest 1.10 → 1.11 (attribute chains)

Two new call shapes get cross-file resolved: 

Cls.method()       Attribute(Name(Cls), 'method')
Cls().method()     Attribute(Call(Name(Cls)), 'method')

If Cls is in imports_map, we look up <target_file>:Cls.method and emit the calls edge. Added 59 new relations on the templedb graph; only shrunk dead-candidates by 3 (from 88 to 85), meaning most attribute-chain calls in this codebase are either same-file or use assignment (svc = get_svc(); svc.method()).

5. Doctor invariant: hygiene_no_untracked_dead_growth

Ambient signal. Fires when a slug's dead_candidates grew by ≥15 in the last 30 days and the adapter version didn't change across the window. The adapter constraint matters: the 1.6 → 1.7 __module__ landing shifted counts by ~110 across all slugs; without the constraint, every resolver improvement would look like regression.

Test suite has three fixtures per this invariant: regression (fires), clean-delta (doesn't fire), and adapter-bump (doesn't fire despite a 60-row delta).

Genuinely on the shelf

  • SCIP for non-Python languages — Phase 4. Wide surface (indexer per language + protocol translation).
  • Log-based projection queue — Q1 recommended replacement for the dual-write pattern. Only the spirit is shipped (via invariant); the real queue is future work.

Small polish still available

  • Class-body decorators for methods — module-scope decorators land on __module__; method-body decorators (e.g. FastAPI @app.route inside a class) are currently unclaimed.
  • templedb ship alias — the seven-command publish recipe I've run ~40 times could be one command. Recommended against in recap 3 for visibility reasons; reconsider if the pattern feels truly stable.

What the recap-3 → recap-4 continuum proves

The observer/integrator plan was primarily about representing knowledge. Recap 3 showed we could ask new questions of the graph (paths, dead-imports). Recap 4 shows we can watch the graph itself change over time — with built-in defenses (the adapter-version check) against our own measurement improvements getting mistaken for reality regressions.

That's what an integrator system looks like when it's stable: facts flow in, invariants watch them, drift produces a signal rather than silently accumulating. Nothing dramatic. That's the point.
