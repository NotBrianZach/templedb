The half-done AST config migration

TempleDB has two config models and only one of them reaches the machine. nixos config (table system_config) is production; config-ast/ast (table config_nodes) is a migration that was started, promoted to exactly one host, and abandoned in August 2026. This consolidates three session findings into one place, because the live generated_file_matches_generator invariant points at this and the remedy it prints is destructive. Facts re-verified 2026-10-10.

Which one is live

Both command groups present themselves as current. What made config-ast look like the successor was the existence of config-ast seed — "seed config_nodes from existing system_config keys" — a one-way migration bridge. That bridge was built and never crossed. 

nixos config   system_config    208 rows   last write 2026-10-04   PRODUCTION
config-ast     config_nodes    1254 rows   last write 2026-08-05   ABANDONED
               ast_builds        27 builds  2 ever promoted, last 2026-08-04

nixos status reads system_config and reports the live rebuild. The hazard is quiet rather than loud: config-ast set succeeds, writes config_nodes, and has no effect on the machine. Both groups now say INCOMPLETE MIGRATION in their --help.

This conclusion was first published backwards, with config-ast named as production. The correction is the finding: the direction of a half-finished migration is not inferable from the existence of a seed command.

Half done across hosts, and the shim holding it together

One host was promoted. hosts/zMothership2.nix is 3 lines — the empty _EMPTY_HOST_MODULE the AST writes on promote — because its overlays were inlined into configuration.nix. Every other host still uses file-based overrides: 

hosts/zMothership2.nix                    3 loc   <- promoted (inlined)
hosts/WilliamZacharyAbelTheZeroth.nix   214 loc
hosts/zachMothership.nix                187 loc
hosts/zMothership3.nix                  126 loc
hosts/zachgigamothers.nix               109 loc
hosts/zStation.nix                       70 loc
hosts/neko-remote.nix                    47 loc   <- added since 2026-10-08

So the split is one inlined host against six file-based ones. The hand-added lib.mkDefault on networking.hostName and boot.loader.grub.enable, carrying the comment "every hosts/<name>.nix overrides via networking.hostName; mkDefault lets those overrides win", is precisely what lets the unmigrated hosts override zMothership2's inlined config.

The hand-edits in configuration.nix are therefore the shim, not drift. Regenerating from the AST deletes the code keeping six machines bootable.

What not to run

generated_file_matches_generator currently reports configuration.nix and home.nix as diverged from config_nodes for zMothership2, and suggests adopting the file: 

templedb config-ast import --replace --scope system .../configuration.nix
Do not run that. import --replace deletes every child of the scope root, and all 409 host-tagged nodes across 5 hosts live under that root. It would wipe the overlays of four machines nothing has tested. Import has no mode that updates shared nodes while preserving host-tagged ones, which is the missing capability behind the whole stall.

The divergence itself is real and expected: the file on disk carries the shim and the generator cannot produce it. Red here means "the AST does not describe the live file", which is the true state of a half-finished migration rather than a file needing repair.

Why the invariant used to be red everywhere

Only 3 of the 1254 config_nodes rows carry a scope at all; those three are the system, home and flake roots. Any database without them — every test fixture, and any install that never adopted config-ast — made generate_file raise ValueError: No root for scope, which the check counted as a violation. That is a check reporting its own inapplicability as a defect. As of 2026-10-10 the no-root case is skipped; genuine comparison failures and genuine divergence still report, which is why the two entries above still appear.

The open decision

Three paths, unanswered since 2026-10-08.

1. Finish it

Add a Comment node type and emission to config_compiler, then re-encode 76 config lines as nodes and 86 as comments. Unblocks completion, but means maintaining a 15-line embedded shell script as a node tree.

2. Draw a scope boundary (recommended)

The AST owns structured settings, authored Nix stays in files, and generate merges rather than replaces. The merge this needs does not exist: docs/AST_MERGE_SEMANTICS.md covers AST-input merging only, not merging into a file that already holds authored content.

3. Retire the AST path

Keep nixos config as the one model and drop config-ast/ast.

The blocking fact for option 1 is concrete: promoting the current build would delete 316 lines of live config, including 86 lines of engineering rationale the emitter cannot represent. Until this is decided the invariant stays red for a legitimate reason, and the remedy it prints stays dangerous.
