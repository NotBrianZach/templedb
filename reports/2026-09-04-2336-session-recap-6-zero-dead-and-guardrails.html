Session recap 6: zero-dead, guardrails, and fleet-sync visibility

Continuation from recap 5. Started with a bug the user spotted (file set writes silently reverted by commit workspace). Ended with hygiene at 0/582 across the entire fleet, a commit guardrail that catches the class of bug that got us there, and the fleet-sync dashboard finally showing the reconcile+scope data the graph has been recording all along.

The user's question that started this

User "is that a problem with the logic of file set or commit?"

Correct diagnosis: neither command is broken alone, but the interaction is a footgun. file set writes DB and records an intent. commit <workspace> scans the workspace and diffs against DB — but doesn't know about intents, so a stale workspace file looks "modified" from DB and gets committed, silently reverting the file set.

The fix

_detect_conflicts in src/cli/commands/commit.py gained a second check. For each modified-in-workspace file, look up applied EditIntents whose new_content_hash matches the current DB blob. If found and the workspace hash doesn't match, flag as a conflict with a distinct reason: 

Your version: workspace (stale)
Current version: DB (via intent #67)
Reason: workspace is behind DB — a `templedb file set` wrote
  this file after the workspace was last synced. Committing
  would revert that write. Refresh with `templedb file cat
  <slug> <path>` > workspace-path, or pass --strategy
  force to overwrite.

Combined with the earlier no-TTY auto-abort (recap 5), a scripted commit that would silently revert now aborts with a clear diagnostic instead. End-to-end tested on a fresh checkout with a real file set → commit sequence.

Two shim resolver improvements got the last false positives:

1.15 — shortest-match for ambiguous imports

import config was resolving to the deep src/cli/commands/config.py when the true target was src/config.py. Sort ambiguous matches by depth, prefer shortest.

1.15b — bind bare import X

from X import Y populated imports_map, but bare import X didn't. Any X.attr reference had nothing to resolve. Now single-name import X and import X as Y bind through to <target>:__module__.

1.16 — same-file assignment tracker

svc = SomeClass(); svc.method() resolves through a simple two-scope map: module-scope + per-symbol overlay. Same-file only. Added +86 relations to the templedb graph without adding any false-dead flags — richer for entity trace/provenance callers queries.

Cleanup receipts

Templedb: 19 files, ~50 imports deleted. Slimevr: 2 files, 2 imports deleted. All 21 files still parse; test suite still 140 passing (same 7 pre-existing failures unrelated to imports). Also caught a real bug during the sweep: 

src/gui.py:455:
  BEFORE: alerts.append("FUSE mount is down ({FUSE_MOUNT_PATH})")
  AFTER:  alerts.append(f"FUSE mount is down ({FUSE_MOUNT_PATH})")

Missing leading f — the alert had been a literal {FUSE_MOUNT_PATH} string that never interpolated. Dead-imports flagged FUSE_MOUNT_PATH as unused because the reference was inside a plain string, not an f-string. Real bug the tool caught by asking "why is this import dead?"
