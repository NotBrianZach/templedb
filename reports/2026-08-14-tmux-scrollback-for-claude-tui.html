tmux config for scrollback in Claude Code TUI under Alacritty + xmonad

Working config for reading Claude Code's scrolled-off output when Alacritty refuses to. Explains why the terminal's Vi mode can't help, why tmux is the right layer for the fix, how to pick a prefix that stays out of xmonad's way, and includes a minimal ready-to-use ~/.tmux.conf. Also sketches a templedb ai vibe start --tmux flag that would apply this automatically.

The problem, precisely

Interactive Claude Code (whether launched directly or via templedb ai vibe start) is a full-screen TUI. Like vim, less, htop, and emacs -nw, it enters the alternate screen buffer (\e[?1049h) on startup and leaves it (\e[?1049l) on exit. That's how these programs guarantee a clean terminal state when you quit — everything they drew disappears.

Alacritty by design does not maintain scrollback for the alternate screen. The primary screen's scrollback (scrolling.history, default 10 000 lines) is unaffected, but while a TUI holds the alt screen, there's nothing above the current viewport to scroll to. This is Alacritty issue #1006, closed WONTFIX with the reasoning that alt-screen scrollback is outside the terminal's contract and other tools (tmux, screen) handle it better.

Consequence Alacritty's Vi mode (Ctrl+Shift+Space) also can't help — it navigates the primary screen's scrollback, not the alt screen. The Vi mode works fine everywhere except inside TUIs, which is precisely where we wanted it.

Why tmux is the right layer

tmux runs a pty per pane and maintains its own scrollback history for that pty, independent of what the running program does with alt-screen escape sequences. Even when Claude Code has taken over the alt screen inside the pane, tmux's copy mode (Prefix [ by default) exposes the pty's full history — everything Claude Code has printed to the pane, all still there, navigable, searchable, copyable.

Better still, with set -g mouse on, wheel-scroll auto-enters copy mode when you're in a TUI, shows the history, and exits back to normal mode when you type. The scroll-back experience becomes almost identical to a terminal that supports alt-screen scrollback natively — because tmux is supplying that layer.

Picking a prefix that doesn't fight xmonad

This part is easier than it sounds: xmonad's key bindings live on Mod (typically Super/Windows or Alt), tmux's live on Ctrl-based sequences. Different modifiers, zero overlap. The choice of tmux prefix is really about ergonomics and bash conflicts, not window-manager collisions.

PrefixTrade-off
Ctrl-b (default) No conflicts anywhere; awkward finger stretch on QWERTY. Fine if you're used to it.
Ctrl-a The classic (GNU screen). Conflicts with bash/readline's go-to-start-of-line — annoying if you use it often.
Ctrl-Space (recommended) No terminal conflicts, easy left-thumb hit, Alacritty passes it through cleanly. Doesn't collide with any common vi/emacs binding you'd use inside tmux either.
Sanity check for xmonad users If your xmonad config uses Mod4 (Super) — the default in most xmonad templates — none of the above tmux prefixes intersect with any xmonad binding. If you've remapped xmonad to Mod1 (Alt), the situation is the same: tmux and xmonad are still in disjoint modifier spaces.

Minimal working config

# ~/.tmux.conf

# --- Prefix: Ctrl-Space (no xmonad/bash conflict) ---
unbind C-b
set -g prefix C-Space
bind C-Space send-prefix

# --- Copy mode: the whole reason we're setting this up ---
bind Escape copy-mode                    # Prefix Esc  → scroll history
setw -g mode-keys vi                     # vi-style navigation in copy mode
bind -T copy-mode-vi v send -X begin-selection
bind -T copy-mode-vi y send -X copy-selection-and-cancel
bind -T copy-mode-vi Escape send -X cancel

# --- Mouse: killer feature for the Alacritty alt-screen problem ---
set -g mouse on                          # wheel-up → auto copy-mode + scroll
                                         # any keystroke → back to normal

# --- Scrollback: don't let one Claude Code turn eat the buffer ---
set -g history-limit 100000

# --- Terminal: preserve Claude Code's true-color rendering ---
set -g default-terminal "tmux-256color"
set -ga terminal-overrides ",alacritty:Tc"

# --- Small quality-of-life ---
set -sg escape-time 10                   # faster vi-mode Escape
set -g base-index 1                      # windows start at 1 (nearer 1 key)
setw -g pane-base-index 1
set -g allow-rename off                  # stop auto-renaming from PS1
bind r source-file ~/.tmux.conf \; display "reloaded"

How to use it

# One-shot session for a Claude Code run:
tmux new "templedb ai vibe start"

# Or start tmux, then launch inside:
tmux
templedb ai vibe start

# Scroll history while Claude Code is running:
#   - mouse wheel up  (auto-enters copy mode, scrolls, wheel-down exits)
#   - Ctrl-Space Esc  (explicit vi-mode entry)
# In copy mode:
#   k / j / Ctrl-u / Ctrl-d / gg / G  — standard vi navigation
#   /pattern <Enter>                  — search backward
#   v  — start visual selection
#   y  — copy selection to tmux buffer
#   Esc — leave copy mode

How the pieces fit together

LayerResponsibilityScrollback role
Alacritty Terminal emulator, renders characters, primary + alt screens Only shows scrollback for primary screen
tmux Multiplexer, owns the pty inside each pane Owns pane history, exposes via copy mode regardless of alt-screen
Claude Code TUI, draws to the pane via alt-screen Doesn't care about scrollback — it repaints per turn
xmonad Window manager, positions Alacritty windows Not involved in scrollback at all

Optional: bake it into templedb ai vibe start

Right now templedb ai vibe start calls subprocess.run(['claude', ...]) in src/cli/commands/vibe.py:279. A --tmux flag could wrap that call in a fresh tmux session using a bundled, minimal config so users don't have to touch ~/.tmux.conf: 

if args.tmux:
    conf = _write_bundled_tmux_conf()      # ships with templedb, ~30 lines
    cmd = ['tmux', '-f', str(conf), 'new-session', '--', *cmd]
result = subprocess.run(cmd, check=False)

Trade-offs:

  • Users without a tmux config get scrollback for free. Bundled config uses Ctrl-Space and mouse-on.
  • Users with their own tmux config get overridden (via -f) for this session only, which may confuse someone who has muscle memory for a different prefix. Behind the flag, so opt-in only.
  • Nested tmux is awkward — if the user is already inside tmux and passes --tmux, they get tmux-in-tmux. Detect via $TMUX and skip the wrap.
Rec Ship the flag, document it, don't make it default. Anyone who wants tmux around everything will already have tmux set up their way. The flag is for someone who just wants scrollback to work in a single Claude Code run and doesn't want to learn tmux's config system for it.

What this doesn't fix

  • Alacritty's Vi mode inside a TUI — still limited to the current viewport. tmux copy mode is the substitute; they don't federate.
  • Scrollback that predates the Claude Code launch — if you were reading shell output before running templedb ai vibe start, that output is in Alacritty's primary-screen scrollback, unreachable while the alt screen is up. You'd see it again after Claude Code exits.
  • Copy/paste out of tmux without a clipboard integration — y in copy mode goes to tmux's paste buffer, not the X selection. Add set -g set-clipboard on plus a working OSC 52 (Alacritty supports it) or install xclip and pipe selections out. Out of scope for the immediate problem.

Alternatives considered

  • Switch terminals to kitty / wezterm / foot — these support alt-screen scrollback via config (kitty: scrollback_lines + alt-screen visibility). Real option if the user is willing. Doesn't solve the "resilient session across SSH drop" property tmux provides for free.
  • Screen instead of tmux — same fundamental fix (multiplexer owns the pty, has its own scrollback), older config language, fewer people know it. If you already run screen, use it; if not, tmux is the modern default.
  • Log Claude Code output with tee — breaks the TUI. Not usable interactively.
  • Ask Anthropic to make Claude Code TUI-optional — it already has -p for print mode (non-interactive), but the interactive experience is the point of vibe start.

Tmux is the right layer because scrollback is a multiplexer concern, not a terminal one, once a TUI is in the alt screen. Ctrl-Space prefix + mouse on + vi-mode copy-mode is enough config to restore the scroll-back experience for Claude Code inside Alacritty. Bundling this behind a vibe start --tmux flag would make it a one-flag opt-in for users who don't want to learn tmux's config language.
