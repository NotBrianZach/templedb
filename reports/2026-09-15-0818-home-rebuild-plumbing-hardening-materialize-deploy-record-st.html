home-rebuild plumbing hardening

Session started with "is there a way to cleanly kill a temple agent session in Emacs?" and ended six commits deeper in the NixOS rebuild path. Along the way: audited/fixed the agent keybindings, discovered the Spacemacs layer, dropped an orphaned pin-current binding, and then — while investigating the CLI plumbing for templedb nixos home-rebuild — found four real sharp edges in the home-manager rebuild service and fixed them. This report covers the rebuild-path half. Agent-side changes are captured in the DB history (intents #285–#291).

Before: what was wrong

templedb nixos home-rebuild <slug> is the "home-only" fast path — skips sudo nixos-rebuild, just re-builds and re-activates the home-manager profile. Reading the source revealed four problems, in decreasing order of severity:

Fix 1 — Materialize before build

home_rebuild() was reading projects.repo_url directly and passing that path to the service, skipping the materialize_from_db() call that switch_system() always runs first. In this codebase, templedb file set usually mirrors writes to the checkout, but "usually" is not "always": if a write goes through a different path (edit-workspace, external tool), the checkout goes stale. A stale-checkout home-rebuild is a silent no-op.

Fix (cli/commands/nixos.py):

-proj = _get_conn().execute(
-    "SELECT repo_url FROM projects WHERE slug = ?", (slug,)
-).fetchone()
-if not proj or not proj[0]:
-    print(f"❌ Project '{slug}' has no repo_url set.", ...)
-    return 1
-checkout_path = Path(proj[0])
+checkout_path = service.materialize_from_db(slug)
+if not checkout_path:
+    checkout_path = service.get_project_checkout_path(slug)
+if not checkout_path:
+    print(f"❌ No checkout for '{slug}'. Import files first: ...")
+    return 1

Bonus: layering is consistent with system_switch() now — both routes materialize via the service, neither reaches into _get_conn() from the handler.

Fix 2 — Record home-only rebuilds

Full system_switch() calls record_deployment() at system_service.py:853 after every successful run. home_rebuild() did not — so home-only rebuilds never appeared in system_deployments, and templedb nixos system-history effectively lied about what had happened on the system.

Fix: after a successful rebuild, insert a deployment row with command='home-switch'. That string distinguishes home-only rows from full-system 'switch' rows at read time, no schema change needed. nixos_generation stays None because the hm generation is a separate numbering — recoverable from the output blob or from ~/.local/state/nix/profiles/home-manager. 

if result['success']:
    try:
        config_path = service.get_config_file_path(checkout_path) or checkout_path
        service.record_deployment(
            slug, checkout_path, config_path, 'home-switch',
            {'success': True, 'exit_code': result.get('exit_code', 0),
             'stdout': result.get('stdout', ''), 'stderr': result.get('stderr', ''),
             'nixos_generation': None},
        )
    except Exception as e:
        logger.warning(f"Failed to record home-manager deployment: {e}")
Design tradeoff Only recording on success matches the existing switch_system() convention. Arguable for home-manager where failures are worth logging too, but consistency won here. If home-rebuild failures start mattering for audit, the same block extends trivially.

Fix 3 — Multi-candidate flake attribute

The old code hardcoded a single attribute path: 

{flake_path}#nixosConfigurations.{flake_output}.config.home-manager.users.{username}.home.activationPackage

This works for the "home-manager as a NixOS module" topology (what zMothership2 uses) and fails silently on standalone home-manager flakes (homeConfigurations.<name>). The failure surfaces as a raw nix attribute-not-found error — no hint that the shape assumption was wrong.

New behavior: try candidates in order until one builds successfully, or until a real (non-attribute) build error occurs. An explicit override via system_config key nixos.home_manager_attr short-circuits the list.

OrderAttributeTopology
0 (if set)value of nixos.home_manager_attrexplicit override
1#nixosConfigurations.<host>.config.home-manager.users.<user>.home.activationPackagemodule (current)
2#homeConfigurations.<user>.activationPackagestandalone, user-keyed
3#homeConfigurations.<host>.activationPackagestandalone, host-keyed

Fall-through only happens on attribute-missing errors, matched via _HM_ATTR_MISSING_MARKERS: 

_HM_ATTR_MISSING_MARKERS = (
    'does not provide attribute',
    'has no attribute',
    "attribute 'homeConfigurations' missing",
    "attribute 'home-manager' missing",
)

Real build failures (compile errors, dependency issues) short-circuit the loop so we don't waste cycles retrying doomed candidates.

Fixes 4 & 5 — Live streaming + per-invocation tempdir

subprocess.run(..., capture_output=True) blocks until the child exits, so users saw: 

  Building home-manager activation package...
  [3 minutes of silence]
  [wall of output]
  ✅ home-manager activated (generation 42)

Meanwhile run_nixos_rebuild() at line 365 already had the correct pattern — Popen + two threads tee'ing stdout/stderr to the terminal while buffering for post-processing. The refactor extracted that into a private helper _run_streaming(), then _rebuild_home_manager() reuses it. 

def _run_streaming(self, cmd, timeout, should_display=None):
    """Popen + threaded tee. Returns exit_code / stdout / stderr / timed_out."""
    stdout_buf, stderr_buf = io.StringIO(), io.StringIO()
    proc = subprocess.Popen(cmd, stdout=PIPE, stderr=PIPE, text=True)

    def _tee(src, buf, dest):
        for line in src:
            buf.write(line)
            if should_display is None or should_display(line):
                dest.write(line); dest.flush()

    t_out = Thread(target=_tee, args=(proc.stdout, stdout_buf, sys.stdout))
    t_err = Thread(target=_tee, args=(proc.stderr, stderr_buf, sys.stderr))
    t_out.start(); t_err.start()
    timed_out = False
    try: proc.wait(timeout=timeout)
    except subprocess.TimeoutExpired: proc.kill(); timed_out = True
    finally: t_out.join(); t_err.join()
    return {'exit_code': proc.returncode if not timed_out else -1,
            'stdout': stdout_buf.getvalue(), 'stderr': stderr_buf.getvalue(),
            'timed_out': timed_out}

The should_display callback preserves the existing quiet-mode filter that run_nixos_rebuild() uses to hide /nix/store/ paths and "copying path" spam. _rebuild_home_manager() passes no filter — it shows everything, since the home-manager build is usually interactive.

The /tmp/hm-activate race got fixed at the same time by wrapping the build+activate in tempfile.mkdtemp(prefix='templedb-hm-') and cleaning up in a finally. Removing the tempdir drops the gcroot; nix keeps the built path alive via the profile symlink after activation, so cleanup is safe.

Fix 6 — Timeout kwargs

Bumped defaults from 10min/5min to 30min/10min (matching run_nixos_rebuild()'s 30-minute timeout), and both are now overridable via build_timeout / activate_timeout kwargs. No CLI surface added — the new defaults are generous enough for any realistic build. 

def _rebuild_home_manager(
    self,
    flake_path: Path,
    build_timeout: int = 1800,
    activate_timeout: int = 600,

Timeouts now return a proper result dict with error and captured output instead of raising past the caller, matching the shape of every other failure branch.

Refactor: run_nixos_rebuild() reuses _run_streaming()

After extracting _run_streaming(), the streaming block in run_nixos_rebuild() (lines 599–662) became a duplicate. Rewrote it to delegate: 

def _should_display(line):  # closes over `quiet`
    if not quiet: return True
    if '/nix/store/' in line: return False
    ...

result = self._run_streaming(cmd, timeout=1800, should_display=_should_display)

if result['timed_out']:
    raise SystemServiceError("nixos-rebuild command timed out after 30 minutes")

return {
    'exit_code': result['exit_code'],
    'stdout': result['stdout'],
    'stderr': result['stderr'],
    'nixos_generation': self._extract_generation_number(result['stdout'] + result['stderr']),
    'success': result['exit_code'] == 0,
}

Net effect: run_nixos_rebuild() dropped from 107 lines to 39. SystemService file lost ~22 lines net despite adding a whole new helper method and a much more capable _rebuild_home_manager().

Not fixed

A handful of sharp edges from the Explore pass remain, none critical:

  • Silent pass in checkout locking (system_service.py:838): git-config failures during sudo-driven rebuilds are swallowed. Almost always fine, but a warning log would cost nothing.
  • Dirty-state check bypass on fresh install (cli/commands/nixos.py:83): returns 0 dirty when nixos.last_generated_at is missing, so first-run protection is missing. Nudge: initialize the timestamp on first successful rebuild.
  • system_rollback CLI arg parsing is muddled — positional deployment_id with nargs='?' whose semantics aren't documented. Needs a real UX pass.
  • Hardware config generation — TODO at services/system_service.py:1808. Untouched.
