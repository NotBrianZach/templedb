2026-09-02 02:27 Own vs observe: TempleDB's fork in the road
Companion to yesterday’s Nix as a projection of TempleDB. That report proposed inverting the authority ordering between Nix and the DB. This one steps back one turn of the wheel and asks a harder question: whether the DB should be an authority over source code at all. Synthesizes three lines of analysis — unpacking “consumers speak the DB protocol,” the standard git multi-copy problem and its standard fixes, and the read-only projection pattern used by every serious static analysis tool — into a single argument. Adds meta-analysis on the identity crisis, the dogfood trap, and the complexity budget. 2026-09-01 Nix as a projection of TempleDB
Design proposal, not implementation. TempleDB and Nix each behave as if they are the ambient source of truth for the same content (Python source, Emacs .el files, NixOS config). The result is drift: five reproducible “edited the wrong copy” incidents in the last month. This report argues that the durable fix is to make Nix a projection of TempleDB — the DB emits derivations, the store paths are named views, and drift becomes a category error rather than a bug. Includes the cheaper interim (templedb file where diagnostic), a mirror inventory, and a rough migration path.
