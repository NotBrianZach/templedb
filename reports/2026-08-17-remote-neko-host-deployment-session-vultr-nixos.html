Standing up a cloud-hosted Neko instance as a Hyperbeam-replacement backend for aireadalong.com’s SitePanel, running on a Vultr VM provisioned end-to-end from zMothership2 via vultr-cli + nixos-anywhere. Session: 2026-08-16 → 2026-08-17.

TL;DR — current state

✓ VM provisioned, NixOS installed with the pre-written services.neko-host module, SSH working via zachKey, NEKO_MGR_TOKEN generated and stored on both the VM and in bza templedb secrets.

✗ Cloudflare Tunnel creds not yet on VM — the existing cloudflare_api_key_json token has Zone/DNS scope but not Cloudflare Tunnel:Edit, so POST /accounts/:acct/cfd_tunnel returns 10000 Authentication error. Once you add that scope (or issue a new token), the remaining steps take ~2 minutes.

How to unblock (all yours)

  1. Open dash.cloudflare.com/profile/api-tokens
  2. Either edit the existing token and add Account → Cloudflare Tunnel → Edit, OR create a new token with Account: Cloudflare Tunnel:Edit + Zone: DNS:Edit scoped to aireadalong.com.
  3. Send me the token. I run: create tunnel → push creds JSON to VM → create DNS CNAME → restart cloudflared + neko-manager.
  4. Flip BROWSER_PROVIDER=neko in bza secrets, redeploy bza. Done.

Session narrative — what actually happened

1. Vultr CLI + API key

Installed vultr-cli v3.8.0 via nix profile. Stored API key in system_config templedb secret. Auth blocked by IP allowlist initially (the token restricts source IPs); you added the machine’s IPv4 which unblocked IPv4-routed calls. IPv6-routed calls still fail — worked around by forcing curl -4 where it mattered.

2. Pre-provision config (system_config)

Wrote hosts/neko-remote.nix, hardwareConfigs/neko-remote-hardware.nix, and a new mkServerHost flake helper alongside mkHost — the existing mkHost always imports configuration.nix + home-manager + woofs/config.nix, which are workstation- oriented and produce cascading conflicts on a minimal server. Added disko as a flake input for declarative partitioning.

4. Three VMs, three lessons

  • VM #1 207.148.5.200 — installed, then unreachable post-reboot. Root cause: my hardware config declared BIOS boot (type = "EF02", efiSupport = false) but Vultr HF uses UEFI. GRUB installed but system wouldn’t boot. Destroyed.
  • VM #2 149.28.245.16 — verified Debian boots UEFI (/sys/firmware/efi present, ESP on vda1). Rewrote hardware config for UEFI + systemd-boot + EF00 ESP. Install succeeded, NixOS booted, but SSH returned Permission denied — my config disabled password auth and never declared root’s openssh.authorizedKeys.keys. Destroyed.
  • VM #3 216.128.143.254 — inlined the zachKey pubkey into users.users.root.openssh.authorizedKeys.keys; zach user inherits the same list. Install succeeded, SSH via key works.

5. Cloudflare tunnel (blocked)

Reused existing cloudflare_api_key_json to look up zone (aireadalong.com = ef21d95...) and account (48e5a8a243...). POST /cfd_tunnel returned Authentication error — token lacks Tunnel scope. Halted before creating a partial/broken tunnel.
