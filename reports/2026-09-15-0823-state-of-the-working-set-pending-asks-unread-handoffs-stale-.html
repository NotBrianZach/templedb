Sessions CLI improvements (landed this pass)

New flags on templedb ai agent sessions and matching changes down the stack:

FlagEffect
--status STATUSFilter by running/waiting/interrupted/created/closed
--provider NAMEFilter by provider (e.g. --provider claude-code to hide fakes)
--min-msgs NOnly sessions with ≥ N messages (skip empty created shells)
--recent-days NOnly sessions updated within the last N days
--limit NRow cap (default 50 — was previously silently truncating)

Output now includes msg_count and pending_asks columns (both text and JSON modes), so stuck asks are visible without opening each session. Store query uses LEFT JOIN subqueries against agent_messages and agent_pending_asks — one round trip regardless of session count.

Example — a workflow to find sessions worth attention:

templedb ai agent sessions --provider claude-code --min-msgs 2 --recent-days 30
templedb ai agent sessions --status waiting        # any provider, waiting only
templedb --json ai agent sessions --limit 500 | jq '.[] | select(.pending_asks > 0)'
